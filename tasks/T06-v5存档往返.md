## 心得

### 1. 归一化被迫分成两层，而**漏掉第二层是个真 bug**

一开始我把归一化整个放在 JSON 层（`sanitizeSessionJson`），以为「解码前洗干净」就够了。
测试直接打脸：`legacySessionGetsAllCompatibilityRulesApplied`、`malformedFieldTypesAreCoercedInsteadOfThrowing`、
`archiveSurvivesFullRoundTrip` 三个用例同时失败 —— `connectedKnowledgeIds` 里的 `kb-quick-notes` 根本没被滤掉。

原因是**解码前的清洗和解码后的归一化解决的不是同一个问题**：

| 问题 | 例子 | 必须在哪里解决 |
|---|---|---|
| **解不开** | `connectedKnowledgeIds` 是字符串、`streamingEnabled` 是 `"maybe"` | 解码**前**（Kotlin 解码器类型不符就抛，`coerceInputValues` 不管这种） |
| **解开了但不对** | `connectedKnowledgeIds` 是数组但含 `kb-quick-notes`、`webSearchEnabled` 是 `false` 而非缺失 | 解码**后**（需要模型的语义） |

现在两层都有测试钉着，不会再漏。

### 2. 最危险的一处：`version` 在导出时**静默消失**

`WwJson` 配了 `encodeDefaults = false`，而 `ArchiveV5.version` 的默认值恰好是 `5`。
于是 `copy(version = 5)` 编码出来**根本没有 `version` 这个键** —— 一个被明文规定
「不可改、跨版本契约、升级兼容分支靠它判断」的字段，就这么无声无息地没了。
`worldGroups` 同理（legacy 存档缺它 → 解码成 `emptyList()` → 等于默认值 → 略过）。

Web 版不会这样，因为 `exportAllData` 是**显式的对象字面量**，17 个键一个不少。
修法是给**顶层**铺一层骨架再叠加实际值（`defaultsJson.encodeToJsonElement(ArchiveV5())`）。

⚠️ 关键是**只铺顶层**：`encodeDefaults` 是递归生效的，拿它编码整份存档会把每个
`ChatSession` / `ChatMessage` 里等于默认值的字段全写出来（`title: ""`、`messages: []` …），
而 Web 版在**嵌套实体**上是 spread 语义 —— 老存档里没有的键就一直没有。铺顶层恰好命中它的语义。

### 3. 归一化必须幂等，否则导出会吃掉合法的 `toolCallStepLimit`

`exportAllData` 走的是 `getSessions()`，所以 Web 版**导出的存档本身就是归一化过的**，
`exportArchive` 必须照做。但这样一来，已归一化的会话会被**再归一化一次**。

第 ④ 条的输入是「原始 `JsonElement`」，第二次归一化时那个原始值已经不存在了。
若 `rawToolLimit` 省略即当 `null`，则合法的 `toolCallStepLimit = 5` 会在**每一次导出时被抹成 `null`** ——
而且没有任何报错，只有工具循环行为悄悄变了。

所以 `normalizeChatSession` 的默认参数是 `session.toolCallStepLimit?.let { JsonPrimitive(it) }`
（用模型自身的值回推等价输入），而不是 `null`。`normalizeChatSessionIsIdempotent` 守住这条。

### 4. MCP 的 `endpoint` → `url` **只能**在 JSON 层做

旧版 MCP 配置长这样：`{"type":"sse","endpoint":"http://localhost:3001/sse"}`。
等解码成 `McpServerConfig` 再判断就晚了：

- `type: "custom_api"` 是**未知枚举值**，会被 `coerceInputValues` 悄悄落成默认的 `streamable_http` ——
  此时已经分不出「本来就是 streamable_http」和「是待丢弃的 custom_api」；
- `endpoint` 模型里根本没这个字段，解码即丢。**两条 SSE 服务的地址就再也找不回来了。**

这是「导入老存档不丢数据」最容易被漏掉的一处，也是本任务**唯一超出原验收范围**的改动
（原验收只点名 `normalizeChatSession`）。做它的理由是：不做的话，legacy 存档里的 MCP 地址会静默丢失，
而「不丢数据」正是本任务写在第一行的可见效果。详见「要点」里对偏差的说明。

### 5. 归一化放在**入口**而不是 **read**，与 Web 版分工不同但可观察行为一致

Web 版把归一化绑在 `Storage.getSessions()` 上：`importAllData` 只把原始 JSON 塞进 localStorage，
真正跑 `normalizeChatSession` 的是之后的读取。原生版没有 localStorage 这层中间态，放在 `parseArchive` 更合适：
落到存储里的数据天然干净，非法值不会先进库再被读出来修。对外可观察的行为完全一致。

### 6. 脱敏的判据错了两次，两次都是「按字段名归类」害的

样本入库要脱敏，仓库里本来有两个脚本（擦密钥、抹正文）。这一天连续漏了三样东西，**每一样都通过了当时的全部检查**：

| 漏掉的 | 藏在哪 | 为什么旧判据看不见 |
|---|---|---|
| 真邮箱 | `webdavConfig.username` | 脚本的清单叫 `SECRET_KEYS`，只列了 `apiKey`/`password`/`authToken` —— **用户名不是密钥**，于是没人往里看 |
| 803 字的对话结构化总结 | `summaries[].content` | 抹除脚本只遍历 `session.messages` —— **总结不是消息**，于是它在遍历范围之外 |
| 账号名 `/mcp/andunya` | `mcpServers[].url` 路径段 | 两个脚本一个管凭据一个管对话，**URL 不归任何一个管** |

三次错误的形态完全一样：**我用「这个字段属于哪个对象、叫什么名字」去判断要不要脱敏**。
而这三样东西分属三个不同对象、三个不同名字，却能用一句话同时抓到：

> **这段内容是不是从「用户这个人」或「这次对话」来的？**

- 是 → 必须处理（邮箱是身份；总结与梗概是对话转写；端点里的账号段是身份）
- 否 → 可以留（配置标签、公共端点、内置默认值）

所以修法不是「再加三个特例」，而是**换判据、并把它写进工具的职责划分**：
`redact` 管**凭据与身份**、`scrub` 管**对话派生文本**、`neutralize-endpoints` 管**个人端点**，
三者互不重叠且都有文档。往后新增字段时，问的是「它是不是从人或对话来的」，
而不是「它看起来像个密钥吗」。

> 附带一条更普适的：**「已核对过没问题」这句话必须逐字段成立。**
> legacy 那份样本的 README 当年写着「其余长文本经核对全是内置默认值，非用户隐私」——
> 那句话在写下的当天就是错的（`plotSummary` 含用户原话）。核对的方法也要可复现：
> 这次是靠**逐字节比对 rich 与 minimal 的全部非会话文本字段**才揪出来的，
> 而不是靠读一遍觉得没问题。

## 要点

- **`version` 与 `exportTime` 无条件写成本次导出的值**（Web 版也是硬编码 `5` / `Date.now()`）。
  它们由 `exportArchive` 显式补写，**不要**以为 `copy(version = …)` 就够了 —— 见「心得 2」。
- **`defaultsJson`（`encodeDefaults = true`）只能用在 `ArchiveV5()` 空实例上**。递归生效，
  拿它编码整份存档会给每个嵌套实体补出一堆键，与 Web 版形状分叉。
- **`redactSecrets` 写的是空字符串 `''`，不是 `null`，也不是删键**。`null` 在 `explicitNulls = false` 下
  会让 `apiKey` 这个键整个消失，恢复逻辑按「是不是空串」判断，两者行为相反。
- **`normalizeChatSession` 是幂等的**，靠 `rawToolLimit` 的默认参数实现。改动它的签名前先看
  `normalizeChatSessionIsIdempotent` —— 不幂等会导致「导出一次就丢一次 `toolCallStepLimit`」。
- **第 ① 条（删 `connectedSkillIds`）由「模型故意不声明该字段 + `ignoreUnknownKeys`」实现**，
  不在 `normalizeChatSession` 里。**不要**为了「完整」把这个字段加回 `ChatSession`。
- **第 ⑥ 条（`streamingEnabled` 非 boolean → `null`）在 `sanitizeSessionJson` 里**，
  `normalizeChatSession` 对它是原样透传（模型层只能是 `Boolean?`）。找这条逻辑别找错地方。
- **六条规则分布在两个函数里**，这是刻意的（解不开 vs 解开了但不对）。两处都必须跑，
  `parseArchive` 里 少一步就会静默漏掉规则。
- **`currentTimeMillis()` 是新的 expect/actual**。T22 加 Android 目标时**必须补 `actual`**，
  否则编译不过（commonMain 没有系统时钟）。
- **fixture 的覆盖边界**：`archive-v5-legacy.json` 是**旧版**真实导出，含 5 条消息、时间线、
  2 篇世界书文档、3 个 MCP 服务、5 个 Skill、`kb-quick-notes`、遗留 `connectedSkillIds`；
  `archive-v5-minimal.json` 是新装空档。**两者都没有**多版本消息、前文总结、分析报告标记、
  窗口绑定的世界书/正则、图片引用、子分支、非空待审批队列、显式 `streamingEnabled` ——
  这些由 `fieldsMissingFromTheFixturesSurviveRoundTrip` 用**合成**样本覆盖，但那替代不了真实样本。
- **worldDocuments 的 `category` 会被丢弃**：legacy fixture 里有这个字段，但 `types.ts` 的
  `WorldDocument` 并不声明它。已核实 React 侧只对 `PromptPreset` 读 `category`，
  世界书文档的 `category` 是死数据 —— 丢弃无害，不构成「丢数据」。
- **legacy 的 `mcp-database`（`type: "custom_api"`）会被丢弃**，这是**照 Web 版行为**
  （`normalizeMcpServer` 对它 `return null`），不是 bug。
- 归一化会**把 `webSearchEnabled` 拍成 `false`、把待审批队列补成 `[]`** 并写进导出。
  看起来像「凭空多了字段」，实际是 Web 版的既有行为（`exportAllData` → `getSessions()`）。
