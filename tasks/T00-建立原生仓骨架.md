## 心得

- **"独立仓"这个选择的真正理由不是洁癖，是 `local.properties`**。它含本机 Android SDK 路径，绝不能提交；若把 Gradle 工程嵌进现有仓，就得同时扩那份 `.gitignore`，而那份 `.gitignore` 里已有 `build/` `dist/` `*.log`，两套忽略规则叠在一起以后很难判断"这个文件到底该不该进库"。
- **fixture 该放在"消费它的仓"，不是"生产它的仓"**。采集是 Web 版做的，但长期读它的是 Kotlin 单测。放在生产方那边，就等于让测试去依赖一个可能被 clone 时漏掉的隔壁仓。
- **进度权威只能有一份**。一开始 `memory/kotlin-migration.md` 和 WORKPLAN 都想记进度，这必然分叉。最后定：WORKPLAN 记进度，memory 只回答"还差什么才能开工"。
- **`.gitignore` 要用 `git check-ignore -v` 验证，不要肉眼看**。我写了 13 条规则，只有被真正命中的才会被确认；肉眼检查发现不了"规则写了但路径形式不匹配"。
- **React 版一旦有人改，函数地图的行号就失效**。所以地图里必须写明"以符号名搜索为准"，并且上游要冻结。

- 新仓分支是 **`master`**（git 默认），未提交任何东西。若统一用 `main`，现在改成本最低。
- **fixtures 位置有意偏离原文档**：原 `BASELINE_COLLECTION.md` §A.1/§C.4 写死 `E:\WatchWorld\WatchWorld\fixtures\`，现改为在原生仓。采集方法不变，只改输出路径。理由记在 `docs/FILE_LAYOUT.md` §2。
- **函数地图行号基准日 = 2026-10-06**，依据 `E:\WatchWorld\WatchWorld\` 当日状态。React 版冻结期间有效。
- **任务文档命名规则**：`tasks/T<两位号>-<简短中文名>.md`。索引登记在 WORKPLAN §二。
- 现有 React 仓内另有记忆体系 `WatchWorld\.claude\projects\e--WatchWorld\memory\MEMORY.md`，与本仓 `memory/` **不互相复制**，避免两份完整副本长期分叉。
