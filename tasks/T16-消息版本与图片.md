## 心得

1. **`regenerateInto` 与 `send` 的生成部分高度重复**。
   理想做法是提取一个 `runGeneration(session, assistantId, query)` 公共方法，但当前 `send` 还承担了 user/assistant 消息创建和标题截断，提取公共方法需要把这些逻辑拆出来。为了不改动已通过 T14 的 8 条用例的路径，选择了「先复制再精简」的策略，`regenerateInto` 是 `send` 的后半段的独立副本。

2. **版本切换必须同步镜像顶层 `latencyMs`/`tokens`**。
   `api.ts:1412 handleSwitchVersion` 会把当前版本的 latency/tokens 复制到顶层字段。这样存档导出时顶层字段始终反映当前选中版本的数据，与 Web 版行为一致。

3. **`editAndResend` 的截断语义**。
   编辑某条 user 消息后，**该消息之后的所有消息都被删除**（`api.ts:1427` 的 `splice` 语义），然后以编辑后的正文重新触发 `send`。这会创建新的 user + assistant 消息对。

4. **滚动重答不新建消息，而是在原 assistant 消息上新增 version**。
   `api.ts:1187 handleRollMessage` 的核心是：在目标消息的 `versions` 数组末尾追加一个空版本，`currentVersionIndex` 指向新版本，然后以上一条 user 消息的正文重新请求模型。生成的内容写入新版本。原有版本不变，用户可以用版本切换箭头回看。
