## 心得

### 1. 文档落后于代码：两份 DDG 解析，只有一份是好的

WORKPLAN §三 T11 与 PLAN §6.5 都指向 `server.ts parseDuckDuckGoResults`，但那用的是
`html.split(/class="result(?:\s|_)/i)` —— `webSearch.ts` 里有大段注释说明这个正则里的 `_`
会连分隔符一起吃掉，而 `result__a`/`result__snippet` 都含 `result_` 前缀，于是整段被切碎、
`/class="result__a"/` 永远匹配不到，表现为「HTTP 200 但解析出 0 条」。
**结论：迁移以源码为准，不以清单文档为准。** 采用 `webSearch.ts` 修好的全局匹配版。

### 2. 原生不需要代理

`webSearch.ts` 的 Web/Android 分流（`searchWebViaProxy` / `parseSearchResponse` / `/api/web-search`、
`/api/skill-search`、`/api/skill-preview`）存在的唯一理由是**浏览器跨域 / 无服务端**。
我们的 Kotlin 是进程内原生应用，没有 Node 服务端也没有 Worker —— 直接调 DuckDuckGo 与
`agent-skills.md` 的 oRPC 即可（PLAN §6.5 也是这个结论）。所以代理层与它的多协议响应解析
（JSON / SSE / NDJSON）整个不迁。

### 3. `new URL(x, base)` 只在 x 没有 scheme 时才套 base

`unwrapDuckDuckGoUrl` 直译时踩到：最初我按「不是 http(s) 就套 `https://duckduckgo.com`」写，
但 JS 的 `new URL('mailto:a@b', base)` 会保留 `mailto:` scheme（它是个绝对 URL）。
若不区分，`mailto:` 链接会被拼成 `https://duckduckgo.com/mailto:a@b` 并被当成合法结果。
正确做法是先判「有没有任意 scheme」，有就原样、没有再套 base。

### 4. 移植 JS 字符串处理时，测试期望要按 JS 语义写

`stripHtml` 把每个标签换成空格再折叠，所以 `A snippet with <b>tags</b>.` 的结果是
`A snippet with tags .`（`</b>` 后留一个空格后接 `.`）—— 不是直觉上的 `tags.`。
同理十进制实体 `&#65;` 是字符 `A` 不是 `65`。这两条一开始都把**测试期望**写错了，
代码反而是对的。移植字符串逻辑时先照 JS 语义推期望值。

## 要点

- **采用哪份解析器**：`webSearch.ts parseDuckDuckGoHtml`（全局匹配 `result__a`、块边界取下一条链接起点）。**不要**改回 `server.ts` 的 split 版。
- **UA 固定**：`Mozilla/5.0 (Linux; Android 14) …Chrome/124…. Mobile Safari/537.36`，DDG 与 oRPC 都用它；DDG 对无 UA 请求返回空结果页。
- **数值边界**：query `trim().take(500)`；`limit.coerceIn(1, 10)`（默认 6）；page `max(1, …)`；pageSize `coerceIn(1, 60)`（默认 8）。
- **oRPC 协议**：`POST https://agent-skills.md/rpc/<router>/<procedure>`，**请求体必须包一层 `{ json: <payload> }`**，响应解包 `json` 字段（缺失 → `Skill 目录返回了无法识别的数据格式`）。
- **文案逐字**：`联网搜索失败：上游限流，请稍后重试`（202）、`联网搜索失败 (${status})`、`联网搜索失败：未取得有效搜索结果，请稍后重试或换关键词`（200 但 0 条）、`Skill 标识格式不正确，应为 owner/repo/skillName`、`该 Skill 没有可用的 SKILL.md 内容`。
- **空结果要抛，不能返回 `[]`**：否则模型会把「搜索失败」当成「已联网但没资料」而擅自作答。
- **`parseSkillFrontmatter` 只认顶层无缩进键**：`metadata` 里的嵌套 `name`/`description` 不能当顶层值。
- **`WebSearchClient` 不持有/不关闭 `HttpClient`**；`searchXxxAt` 是 `internal`，只为测试注入假上游地址。
- **接进对话流程归 T14**：本任务只给可复用客户端与格式化函数，`shouldUseWebSearch` 的调用点与 system 注入在 T14。
