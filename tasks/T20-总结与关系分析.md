## 心得

### 1. 复用 `runToolChat` 做一次性请求，但它「失败不抛、写 note」——必须自己转异常

总结与分析都是一次**非流式、无工具**的模型调用。为了不重写三家 Provider 的请求体，
直接复用 T09 的 `runToolChat`：`activeMcpServers = []`、`activeSkills = []`、`stream = false`，
它就退化成一次普通请求。

但 `runToolChat` 的既定契约是「除取消外不抛，失败转 note」。空回复会被写成
`[模型未返回最终正文]` 并**原样返回**，于是第一版直接把这句话存成了**总结的正文** ——
测试 `generateSummaryEmptyReplySetsErrorWithoutTouchingSession` 抓到了。

修法：`oneShotText` 把 known 失败 note 与空串转成异常（`isOneShotFailure`），
正好对齐 Web 版 `sendChatMessage` 抛错的语义 —— 总结写 `summaryError`、分析走兜底报告。
这条对**所有**「拿模型输出当最终数据」的一次性调用都适用，别只当成本任务的特例。

### 2. `publish` 必须改成 `copy`，否则一次流式回调就清掉面板的临时标记

`publish` 原来新建 `ChatUiState(session, streamingId, error)`。总结过程中 `summarizing` 会
被随后的任何 `publish`（例如流式回调，或分析里的占位消息发布）重置为 `false`，
面板上的「总结中…」会闪一下就没了。改成 `mutableState.value.copy(...)` 后，
`summarizing`/`summaryError`/`analyzing` 这些与单次消息流无关的标记得以保留。
对既有测试无影响（它们只读 `session`/`streamingMessageId`/`error`）。

### 3. 「省 Token」的关键不是加总结，而是**推进 `lastSummarizedFloor`** 

`buildSystemInstruction` 只把总结拼进 system tail；真正省钱的是 T08 就做好的
`dropSummarizedFloors`：它按 `lastSummarizedFloor` 把已总结原文从送往模型的历史里剔除。
只加总结却不动 `lastSummarizedFloor`，等于**总结与原文各发一份，Token 不减反增**。
所以 `generateSummary` 成功后必须推进该字段；`clearSummaries` 则**故意不动它**（与 Web 版一致）。

### 4. 分析失败在 Web 版是「内部 catch 返回兜底」，不是抛

`api.ts analyzeRoleRelationships` 自己 `try/catch` 并返回 `### 📊 角色关系分析 … 分析功能暂不可用`，
所以上层 `handleTriggerRoleAnalysis` 的 catch 几乎不会触发。原生照此：
`oneShotText` 抛异常 / 没有 Provider / 返回值空白 → 都写入 `buildRoleAnalysisFallback(branch)`。

⚠️ 但注意 one-shot 的**失败 note 已被转成异常**（心得 1），所以上游 500 时原生写的是
兜底报告（与 Web 版一致），而不是工具循环那句 `[请求失败：…]`。

### 5. 曾以为 `analysisVisibility` 会过滤上下文，实际只改徽章 —— 后续把它做成真过滤

徽章文案写着「不占AI上下文」，但 `grep analysisVisibility src/lib src/App.tsx` 显示：**只有 UI 徽章与切换逻辑引用它，`api.ts` / `timelineMemory.ts` 都不读**。
第一版原生**照抄这一现状**（只做展示开关）。后来确认这就是 bug，于是补做了真过滤 —— 见「心得 6」。

### 6. 让「不占AI上下文」真正成立：三处调用点都要过滤，且 Web/原生必须同步

徽章不能只是文案。只要有一条路径把隐藏报告发给模型，这个承诺就破了：

1. **正式对话** —— `ContextBuilder.build` 第 0 步过滤（必须在 `aiContextVisibility` 之前，
   否则隐藏报告会占掉 `latest_custom` 的助手消息名额）；
2. **前文总结** —— `summaryRange` / `unsummarizedMessages` 都只算过滤后的消息，
   否则隐藏报告被总结后，又经总结回到了上下文；
3. **下一次角色分析** —— 分析上下文在插入新占位消息**之前**快照，并过滤隐藏报告。

判据统一为：**`isAnalysis == true` 且 `analysisVisibility` 明确为 `HIDDEN` 才剔除**；
缺省（`null`，老存档）视为可见 —— 与 UI 的 `?? VISIBLE` 一致。

**Web 版同步改**（用户明确要求两边行为一致）：`api.ts sendChatMessage` 新增
`contextSourceMessages`；`App.tsx` 的 `handleGenerateSummary` 与 `handleTriggerRoleAnalysis`
各自过滤。改完跑过 `npm run lint`（`tsc --noEmit`）通过。

> ⚠️ 这是少见的「**主动动规格书仓**」：React 版是只读参照，但这条行为差异若不改，
> 两边同一条会话会得出不同的模型结果。以后凡涉及「送模型的内容」，都要先想清楚是不是两边都要改。

## 要点

- **`DEFAULT_SUMMARY_PROMPT` 在 `data/DefaultData.kt`**，改它等于同时改「全新安装」与
  「老存档缺字段」两处的行为；面板留空时用它。
- **总结文本格式**：`#<楼号> [<codeTag>] <用户|AI>：<正文>`，条间空行；
  正文取值链 `versions[currentVersionIndex] → versions[0] → content`（`||` 把空串当假）。
- **分析上下文格式**（与总结不同）：`[<codeTag|通用>] #<楼号|1> <用户|AI>: <正文>`，条间换行，
  楼号缺失时兜 **1**（总结兜 **0**）。
- **`oneShotText` 把失败 note 转异常**：`[模型未返回最终正文]` / `[响应意外中断…]` /
  `[模型停止：…]` / `[请求失败：…]` 与空串都算失败。新增一次性调用时若还要复用 `runToolChat`，
  必须同样处理，否则会把 note 当正文存下来。
- **`ChatUiState` 的 `summarizing`/`summaryError`/`analyzing` 靠 `publish` 的 `copy` 保住**，
  改 `publish` 时不要退回「新建 `ChatUiState`」。
- **总结成功后必须推进 `lastSummarizedFloor`**（省钱所在）；`clearSummaries` **不回退**它。
- **总结失败只写 `ChatUiState.summaryError`**，不落消息、不动会话（与 Web 版 `summaryError` 一致）。
- **分析消息字段**：`isAnalysis = true`、`analysisVisibility = VISIBLE`、`codeTag = "分析"`、
  `descriptionTag = "角色心理博弈"`、`analysisBranchCode = 当前分支 codeTag`、
  `floorNumber = maxFloor + 1`（⚠️ 之后不会再重排后续楼号，与 Web 版一致）。
- **分析归档固定写入 `groupId = "wg-analysis"`**（`App.tsx:1912` 硬编码），
  文档 `id = "doc-analysis-<时间戳>"`、标签 `["角色分析", codeTag]`。
- **`analysisVisibility == HIDDEN` 的分析报告不进模型上下文**：由 `dropHiddenAnalysisMessages` 统一判定
  （`isAnalysis == true` 且明确为 `HIDDEN`；缺省视为可见）。三处调用点都已接：
  `ContextBuilder.build`（第 0 步）/ `Summary.summaryRange`+`unsummarizedMessages` /
  `ChatViewModel.analyzeRoleRelationships` 的上下文快照。
- **Web 版（规格书仓）已同步同一过滤**：`api.ts sendChatMessage` 的 `contextSourceMessages` +
  `App.tsx` 的 `handleGenerateSummary` / `handleTriggerRoleAnalysis`。改任一边都要同步另一边。
- **`dropHiddenAnalysisMessages` 只改「送往模型的内容」，不动会话本体**：UI 仍完整展示，
  导出/存档也照旧保留隐藏报告。
- **模型回退链**：总结 = `override || session.model || preferences.defaultModels.summary || provider.defaultModel`；
  分析 = `session.model || preferences.defaultModels.analysis || provider.defaultModel`（无 override）。
- **`SummaryPanel` 是 `FeatureDialog` 的内容区**（`scrollable = true`）：总结列表用
  `heightIn(max=…) + verticalScroll` 限高，**不要再**套一层整页滚动，否则内层高度算不出来。
- **侧边栏新增 `onOpenSummary`**：`SidebarSheet` 底部导航第 9 个入口（`TablerIcons.FileText`）。

## 遗留问题 / 下一步

- **分析报告不能流式显示**：现在先插入占位消息、拿到整段报告后一次性回填（与 Web 版
  `analyzeRoleRelationships` 的非流式调用一致）。要流式需另立方法。
- **总结/分析的模型选择是纯文本框**：Web 版从 Provider 的模型列表下拉选；原生还没做
  「拉模型列表」（`fetchModelsFromProvider` 未迁），所以只能手填。模型列表属后续 Provider 任务。
- **`analysisVisibility` 的显示不带主题化卡片底色**：Web 版分析气泡有独立渐变底色；
  原生沿用普通 AI 气泡 + 徽章，视觉打磨属后续。
- **面板只做了编译与逻辑验证，没有真窗口截图走查**：缩进/按钮观感属未验证项。
- **`archiveAnalysisToDocument` 不弹提示**：Web 版 `alert('已归档…')`；原生没有 toast 机制，
  静默成功。需要提示时随 UI 打磨一起加。
