## 心得

- **`ChatSession` 没有按 PLAN §4.3 拆成 `SessionConfig` + `SessionEntity` + 聚合对象 —— 这是本任务唯一一处偏离方案的地方，理由是形状而非偏好。** PLAN §4.3 拆出的三块是**落库**（T07）的形态；而 `ChatSession` 同时是 **v5 存档里的形状**（`exportAllData()` 直接序列化整个对象）。若在模型层就拆开，T06 的 `v5 JSON → 内存 → v5 JSON` 往返测试就得先写一层重组/再拆分，等于把「存档契约 ↔ 存储实现」的映射提前塞进模型层。故本类保持与 `types.ts` 逐字段对齐，作为**存档契约的唯一权威**；T07 再引入 `SessionConfig` / `SessionEntity` 与两者之间的映射，**映射放在 `data/` 层，不改本类**。
- **`explicitNulls = false` 的坑，实测踩了一次**：它只把「因为默认值而省略」和「显式 null 但等于默认」写成缺字段；**显式传入 `null` 且字段没有默认值时，仍会写成 `"key": null`**。所以「给可空字段配默认值」不是风格问题，是这条配置生效的前提。反过来说：本仓约定 —— **新增可空字段必须给 `= null` 默认值**。
- **枚举的容错靠默认值，不靠 `isLenient`**。`coerceInputValues` 只在字段**有默认值**时才把未知 enum 退回默认值。于是产生一条可照抄的判断规则：这个字段的取值猜错了会怎样？——猜错代价大（如 `fileAccess` 权限）就不给默认值，让它抛错；猜错无所谓（如 `provider.type`）就给默认值。
- **归一化全部推给 T06，模型层只声明 `Int?` 而不做钳制**。理由：把 `toolCallStepLimit` 的 `max(0, floor(n))` 写进模型层，就等于把「读老存档」的规则藏进类型定义里，T07 落库时会有第二份实现，两份必然漂移。代价是 **T06 反序列化时要保留原始 `JsonElement`** 才能对非数值输入做判断（`MIGRATION_CONSTRAINTS.md` §2 第 ④ 条已按此写过示例）。
- **`uiMode` 保留原始 `String?` 而不是直接上 `UiMode` 枚举**：legacy 与 minimal 的值分别是 `"light"` / `"dark"`，两个枚举值都在，用 enum 也没问题；但存档里它是「一个字符串」，回写时原样透传比枚举往返更不容易出岔子。真正需要类型的地方（主题解析）再转换。

## 要点

- **本仓的字段名一律不许改**（`codeTag` / `descriptionTag` / `floorNumber` / `isCommon` / `guanjie_*`）：每个都对应存档字段，改名即破兼容。`MIGRATION_CONSTRAINTS.md` §6 的表就是这份模型的文件级注解。
- **故意不声明** `ChatSession.connectedSkillIds`（遗留字段）。Kotlin 侧不声明 + `ignoreUnknownKeys` 丢弃，与 `normalizeChatSession` 第 ① 条的删除效果一致；**不要**为了「完整」把它加回来。
- **`streamingEnabled` 的三态目前只由模型声明保证，没有任何代码强制**：它是 `Boolean? = null`，**没有默认值**（若有人「顺手」写成 `= false`，所有老存档会集体变成非流式）。守住它的是 `ArchiveV5ModelTest.unnormalizedStreamingFlagKeepsThreeState`；改这个字段前先看那条测试。
- **`versions` 必须允许空数组**（真实存档里 user 消息就是 `[]`，正文在顶层 `content`，且没有 `latencyMs`）。任何 `versions.first()` / `versions[0]` 都是 bug，取值前先看 `role`。
- **`ArchiveV5` 的集合字段全部给空数组默认值**，因为 `importAllData` 是逐项 `if (data.xxx)` 判断、不做版本校验；`archive-v5-legacy.json` 实测就**缺 `worldGroups` 与 `appPreferences` 整个字段**（不是空数组）。别把「字段缺失」当成异常。
- **`explicitNulls = false` 也意味着读的时候分不清「字段缺失」和「字段是 null」**。现有 TS 代码对这两者本来就同样处理（都是 `undefined`/falsy），所以不构成兼容问题；但将来若有字段需要区分，得改回 `explicitNulls = true` 并逐字段处理 —— 那会是一次破坏性改动。
- **`ArchiveV5.theme` 是单数、`worldDocuments`/`worldGroups` 是复数**，且 `theme` 是**字符串**（内置 id 或 `custom_xxx`）。用户 DIY 主题存在另一个键 `guanjie_custom_themes`，**不进这个存档**。
- **启用序列化插件的位置**：`org.jetbrains.kotlin.plugin.serialization` 版本跟随 `kotlin`（2.4.20），**必须与 Kotlin 版本一致**；它只在 `shared` 上 apply。
- **`WwJson` 全局只有一个实例**（协议层 SSE 帧解析与数据层共用）。改它的任何一项配置都会同时影响 `net/` 与 `model/`。
