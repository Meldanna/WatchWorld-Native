## 心得

### 1. 取消路径里不能再调 suspend 回调

TS 在 AbortError 分支里 `note('已停止生成')` 后 `return visible`。原生版若在 `catch (CancellationException)` 里调 `note()`，它内部的 `onChunk`/`onNote` 是 suspend 回调，协程已取消，会**立刻再抛一次** `CancellationException`。所以取消分支只做 `throw error`，提示由调用方（T14 `ChatViewModel`）补；已输出正文调用方从自己的 `onChunk` 累积里取。

### 2. Claude 的 adapter 每轮都要新建

Claude 的 block 表是跨事件的有状态对象。复用上一轮的 adapter，会把上一轮的 `content_block_start` 当成已开始，第二轮解析错位。`runToolChat` 每轮 `ProviderStreamAdapters.forProvider(kind)` 新建一份。

### 3. Gemini 的 `functionResponse.response.result` 是对象

OpenAI 的 `content`、Claude 的 `tool_result.content` 都是**字符串化**后的 JSON；Gemini 是 `response: { result }`，`result` 是**对象本身**。照前两家写成字符串，Gemini 不报错但语义变了。`geminiRoundsUseFunctionCallAndFunctionResponseParts` 断言 `result` 是 `JsonObject`。

### 4. OpenAI 回填 tool_calls 要带 `type: "function"`

流里只有首帧带 `type`。回填 assistant 消息时不补，第二轮请求里 tool_calls 形状不完整。`openAiToolCallsAreRebuiltWithTypeAndConcatenatedArguments` 守住；`name`/`arguments` 按 index 用 `+=` 串分片。

### 5. 有意不迁的两处

- `viaProxy` 分支（Cloudflare Worker / 同源 `/api/chat`）与只服务它的 `emitPlainReply`：桌面端是进程内应用，没有 Worker。
- 非流式的 `replayAsStream` 回放：那是 Android WebView 拿不到增量的补偿，桌面端已是真流式，回放只会凭空拖慢。

## 要点

- **`ToolDefinition.name` 是注册名、`originalName` 是原始名**（字段名有点绕）。`McpToolCaller` 收到的是**原始名**；改注册规则必须同步改 `ContextBuilder` 的 MCP 能力清单（CONSTRAINTS §3.3）。
- **工具清单的唯一来源是 T08 的 `AssembledContext.availableMcpServers` / `availableSkills`**，别另行过滤。
- **除取消外不抛异常**：失败作为 `note` 追加进正文；工具错误转 `{ "error": … }` + `isError` 交给模型。
- **finish_reason 白名单**：OpenAI `stop`/`tool_calls`，Claude `end_turn`/`stop_sequence`/`tool_use`，Gemini `STOP`。白名单外或缺失 → note 后结束，不执行本轮工具。
- **`toolCallStepLimit`**：`0` = 不限，负数抛错；达到上限在**执行完本轮工具之后**停，不再发下一轮。
- **Gemini 的 key 走 `?key=` query**；非流式要把 `:streamGenerateContent?alt=sse` 换成 `:generateContent`；Gemini 只传 temperature / topP / topK / maxOutputTokens，惩罚项不传（TS 原样）。
- **思维链只展示**：跨轮 `\n\n` 拼接，不进 history、不进 visible。
- `ollama` 不要求 API Key（与 TS 一致）。
