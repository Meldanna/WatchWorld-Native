## 心得

1. **用泛型简化 9 类配置的 CRUD。** `SettingsViewModel` 里每种配置的 save/delete 逻辑几乎一样（读列表 → 按 id 匹配 → 替换或追加 → 全量写回），抽成 `upsert` / `remove` 两个 private 泛型方法后代码量砍一半，且新加一种配置只需两行。
2. **主题切换不需要重启。** `WwTheme` 本身就是 `@Composable`，palette/uiMode 变化后 Compose 自动重组；`SettingsViewModel.setThemePalette` 写库 + 更新 StateFlow 即可触发。
3. **Row 的位置参数顺序：** Compose 的 `Row(modifier, horizontalArrangement, verticalAlignment, content)`，把 Arrangement 放第一个会被当作 Modifier 导致类型不匹配。必须用命名参数或严格遵循位置顺序。
4. **`HardcodedChatProvider` 暂未删除。** 分析后发现 `ChatStreamClient.streamAssistantEvents` 仍引用它（T03 的临时单轮路径），`ChatStreamClientTest` 的 2 个用例也依赖它。删除需要把那条路径也改走 ConfigRepository，影响面超出 T15 范围；标记为遗留，在 `ChatStreamClient` 正式接入多 Provider 路由时一并清理。

## 要点

- **写操作全走 Repository**：`SettingsViewModel` 不碰 DAO，所有写用 `ConfigRepository.transaction { }` 包事务，防并发写互相吃改动。
- **`testRegexRule`** 是 `regexProcessor.ts:26` 的直译：对单条 RegexRule 跑一次替换返回结果。设置界面用来做正则实时预览。`flags` 为空时按 JS 惯例默认加 `g`。
- **App.kt 的 `WwTheme` 参数**：palette / customThemes / chatFontSize / uiMode 四个全从 `settingsState` 读（不再写死 `"emerald"`）。uiMode `"dark"` → `UiMode.DARK`，`"light"` → `UiMode.LIGHT`，其他 → `null`（跟随系统）。
- **设置面板遮盖聊天区**：`settingsOpen == true` 时 `SettingsHub` 替代侧边栏和聊天区，避免三栏同时挤压。关闭设置回到正常布局。
- **SettingsViewModelTest** 用 `WwDatabase.openInMemory()` 跑，不碰磁盘，不碰网络。6 用例覆盖 CRUD + toggle + 持久化 + 导入导出往返。
- **不改字段名 / 存储键 / version**：本任务只加 UI 层和一个纯函数，不动模型层。
