## 心得

### 1. system 段落顺序：约束文档与源码不一致，以源码为准

`MIGRATION_CONSTRAINTS.md` §4.1 与 PLAN §6.6 写的是「世界观 → 知识库 → MCP → Skill → extraSystemTail」，
但 `api.ts:311-321` 的真实顺序是：

```
人格/窗口指令(head) → 世界观正典 → MCP → Skill → 知识库 → 联网结果 → 楼号约定 → extraSystemTail → 时间线树
```

源码注释写明了原因（「稳定性从高到低，利于 Prefix Cache；知识库垫在能力清单之后」）。迁移第一原则是「TS 是规格书」，所以按源码实现，并由 `systemSectionsFollowApiTsOrder` 钉死整串。经用户确认，已按源码修正 `MIGRATION_CONSTRAINTS.md` §4.1 与 `KOTLIN_MIGRATION_PLAN.md` §6.6。

### 2. 正则不能直接交给 Kotlin `Regex.replace`

替换串语法两边不同：JS 的 `$&`、`$$`、`$<name>` 在 Kotlin 里要么不认、要么抛错，反斜杠在 Kotlin 是转义符而 JS 不是。再加上 JS「无 `g` 只换一次」和 `rule.flags || 'g'`。照字面直译会让同一条用户规则在两版输出不同，且没有报错。所以替换串自己按 ECMAScript GetSubstitution 展开。

### 3. 时间线开启时正则结果被覆盖 —— 用方案 A 修掉（有意偏离 TS）

`api.ts:333-340`：先 `applyRegexRules` 改写 `content`，接着若 `timelineMemoryEnabled` 就 `content = formatMessageWithFloorAndTag(m, …)`，后者重新读**原文**，于是时间线模式下正则对历史消息不生效。

候选三种：A 正文先过正则再加前缀；B 加前缀后整串过正则（用户规则会碰到前缀，`^` 开头的规则失效）；C 保持 TS 现状。经用户批准选 **A**：`formatMessageWithFloorAndTag` 新增 `content` 参数（默认仍取原文，其它调用方行为不变），`ContextBuilder` 传入已过正则的正文。由 `timelineMemoryKeepsRegexResultAndLeavesTagPrefixUntouched` 守住。⚠️ Web 版仍是旧行为，两版在此处输出不同。

### 4. JS 假值语义逐处对齐

- `floorNumber == 0`：TS `!message.floorNumber` 为真 → 不参与推入通用过滤、也不写 `#0` 前缀；
- `latest_custom` 的 `slice(-limit)`：`limit = 0` 时是 `slice(0)` = 全部保留，而不是「一条都不留」；
- `systemInstruction || agent.systemPrompt`：空串退回人格提示词；
- `codeTag || tag || '通用'`、`m.description || '无'`：空串都要退回。

### 5. 联网与图片不在拼装层里做

TS 在拼装中途 `await searchWeb` / `ImageStore.getMany`。原生版拆开：联网结果由调用方作为 `webSearchContext` 传入（T11 实现搜索，`AssembledContext.latestUserQuery` 已给出判定输入），图片只保留 `imageIds` 引用（T21 实现读取）。这样 `ContextBuilder` 是纯函数，可完全单测。

## 要点

- **system 顺序以 `api.ts:311-321` 为准**，与 CONSTRAINTS §4.1 文字不同（见「心得 1」）。改顺序前先看 `systemSectionsFollowApiTsOrder`。
- **三个段落标题常量以 `\n\n` 开头**，拼接时再用 `\n\n` join，所以段与段之间实际是四个换行 —— 这是 TS 原样，不是多写了。
- **`AssembledContext.availableMcpServers` / `availableSkills` 是 T09 工具注册的唯一来源**：system 清单与注册工具必须出自同一份过滤结果，否则模型会报「未授权的工具」（CONSTRAINTS §3.3）。
- **MCP 清单里的类型用存档字面量大写**（`STREAMABLE_HTTP` / `SSE`），由 `wireName()` 给出，不依赖 Kotlin 枚举名。
- **正则走 `RegexApplyScope.OUTPUT`**（发给 AI 的历史）；`scope = both` 两个方向都生效。JS 与 Java 正则方言仍有残余差异（如 `y`/`u` 标志、个别 Unicode 属性），`y` 视为非法跳过，`u`/`d` 忽略。
- **时间线开启时正则照常生效，前缀不过正则**（方案 A，有意偏离 TS，见「心得 3」）。不要把 `ContextBuilder` 里传给 `formatMessageWithFloorAndTag` 的 `content` 参数删掉。
- **`buildSystemInstruction` 的窗口指令**：`systemPromptFixed || systemPromptOverride`，空串的 Fixed 会退到 Override。
- **`selectActiveWorldDocuments`：`connectedWorldDocIds == null` = 全部文档**；`[]` = 一篇不选。两态别合并。`selectActiveRegexRules` 同理。
- `ContextBuilder` 不读库、不联网、不读图，纯函数；调用方从 Repository 取数据后组装 `ContextRequest`（UI 不碰 DAO）。
