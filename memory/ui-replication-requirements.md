# WatchWorld Native UI 复刻统一要求

> 本文件集中记录从参考项目复刻 UI 时必须遵守的视觉、架构、弹窗与导航规则。

## 一、参考源与实现原则

- 参考 UI 源码目录：`E:\WatchWorld\WatchWorld`。
- 当前实现项目：`E:\WatchWorld\WatchWorld-Native`。
- 参考项目决定功能配置、显示逻辑、交互行为和视觉规范。
- Native 项目决定具体实现方式，统一使用 Kotlin Multiplatform、Compose Multiplatform、Material3、现有 DesignTokens 与现有状态管理架构。
- 不得直接复制 React、TypeScript、Tailwind CSS 或其他非原生窗口代码。
- 不得为了复刻 UI 创建与现有会话、窗口、设置状态互不相通的重复持久状态。
- 图标不要求与参考项目资源完全一致，可使用 Native 项目中语义一致、线条风格统一的 Tabler 图标。

## 二、覆盖层与弹窗统一规范

所有侧边栏、设置页和功能弹窗均作为主界面上方的覆盖层显示，不得替换或挤压聊天主界面。

> ⚠️ **例外：桌面端侧边栏改为「停靠」**（用户 2026-10-13 定案，优先级高于本条）。
> Windows／桌面窗口宽，侧边栏固定展开成内容左边的一列（挤窄内容区），不再是覆盖层；
> Android 窄屏保持覆盖层抽屉（默认收起）。形态由 `ui/sidebar/SidebarLayout.kt` 的
> `defaultSidebarLayout` 按平台定（桌面 `DOCKED`、其余 `DRAWER`），见 §四。

### 统一视觉

1. 弹窗默认采用居中浮动形式，不全屏铺满；普通功能弹窗最大宽度为 600dp。
2. 内容较少时高度随内容自适应；内容较多时最大高度为可用窗口高度的 85%，超出后仅内容区滚动。
3. 标题区固定，不随内容滚动；标题位于左侧，关闭图标位于右侧，关闭图标统一使用语义一致的 Tabler 图标。
4. 弹窗统一复用 `FeatureDialog` 或后续等价的公共弹窗壳，不得在各功能面板重复实现不一致的遮罩、标题栏、圆角和滚动行为。
5. 默认由弹窗壳管理内容滚动；只有内部已自行管理滚动的复杂布局才关闭外层滚动。
6. 遮罩、Surface、文字、边框、强调色和悬停反馈统一读取主题令牌，不写死只适用于亮色主题的颜色。
   **遮罩只有一款**（用户 2026-10-13：「检查遮罩，所有的遮罩，把它们统一款式，毛玻璃效果，不用压黑」）：
   一律用 `WwModalScrim(onDismiss = …)` 铺（它自带 `WwSurfaces.scrim` + 「点外面关闭」+ 模糊登记），
   不得再手写 `Color.Black.copy(alpha = …)` / `colorScheme.scrim` 当遮罩。
7. **分层底色必须带主题倾向**：弹窗底板用 `WwTheme.colors.surfaceElevated`；底板上的一层卡片用 `WwSurfaces.card` / `cardStrong`，凹槽用 `inset`，选中用 `cardSelected`，描边用 `cardBorder`。
   ⚠️ **不得**用 `MaterialTheme.colorScheme.surfaceVariant` 当卡片底 —— 它在本主题体系里是纯中性灰（`--surface-3`），铺出来是一块块「灰白框」，与主题色脱节。
   完整函数地图与五条配色坑见 [`theme-color-map.md`](theme-color-map.md)。
8. **所有弹窗都必须支持点击弹窗外关闭当前层**：在弹窗卡片/内容区域之外提供可点击遮罩，并调用与标题栏关闭按钮相同的返回回调；不能依赖平台 Dialog 对“窗口外点击”的默认处理，因为 Dialog 自身可能占满窗口，视觉上在弹窗外的点击仍落在 Dialog 内部。
9. 点击弹窗卡片及其内部内容不得关闭弹窗；卡片内部必须拦截点击，避免事件传递到关闭遮罩。此规则适用于普通弹窗、全屏或大尺寸弹窗、子弹窗和图片预览等覆盖层。

## 三、统一关闭与返回上级规则

所有弹窗和覆盖层必须维护清晰的界面层级。关闭行为的含义统一为“返回上级界面”，而不是简单关闭全部界面状态。

以下操作必须执行同一套返回逻辑：

- 点击当前弹窗标题栏中的关闭按钮。
- 点击当前正在显示的弹窗卡片/内容区域之外的遮罩区域。**这是统一必备行为，不得仅依赖 Dialog 默认外部关闭**；必须关闭最上层，并沿用标题栏关闭入口相同的返回逻辑。
- 使用系统返回键、桌面返回快捷键或平台提供的返回操作。

统一行为：

1. 从聊天主界面直接打开的一级弹窗，关闭后返回聊天主界面。
2. 从侧边栏打开的功能弹窗，关闭后返回侧边栏，并保持侧边栏打开前的列表位置、搜索条件和折叠状态。
3. 从设置总入口打开的二级设置弹窗，关闭后返回设置总入口，而不是直接回到聊天主界面。
4. 从某个功能弹窗继续打开的子弹窗，关闭后返回发起它的父弹窗，并尽可能保留父弹窗的编辑内容、滚动位置和当前选项。
5. 只有用户明确关闭上级界面时，才继续返回更上一级。
6. 同一时刻只能有一个最上层弹窗接收关闭、遮罩点击和返回事件，事件不得穿透到父层或聊天主界面。
7. 点击弹窗内部区域不得触发遮罩关闭；拖动、滚动、下拉框、菜单与子弹窗操作也不得误触发父弹窗关闭。
8. 存在未保存编辑时，应沿用该功能的保存或放弃策略，不得因遮罩点击静默丢失数据。

实现时优先使用明确的导航栈或父界面来源状态，例如 `DialogDestination` 与 `returnDestination`，避免用多个互相独立的 Boolean 导致关闭后无法判断应回到哪个上级页面。

## 四、侧边栏入口调用规则

- 从聊天主界面打开侧边栏时，侧边栏覆盖在聊天区之上（**仅抽屉形态 / Android**）。
- **桌面=停靠、Android=抽屉**（用户 2026-10-13）：
  - `DOCKED`（`defaultSidebarLayout` 在桌面返回它）：侧边栏是主布局里的一列，内容区被挤窄、不被遮挡；
    初始展开，顶栏菜单按钮 / 侧边栏 ✕ 收起或展开这一列。面板与抽屉形态**共用同一份参数**
    （`App.kt` 里抽成 `sidebarPanel` lambda，避免两处各拼一份导致漏接回调）。
  - `DRAWER`：保持覆盖层 + 毛玻璃遮罩，初始收起，点遮罩关闭。
  - 形态只按平台定，**不按窗口宽度自适应**（用户是按平台描述的诉求）；初始展开状态不落库（重启回到默认）。
- 从侧边栏进入功能弹窗时，应记录来源为侧边栏，再显示目标弹窗。
- 目标弹窗关闭后恢复侧边栏，而不是直接回到聊天界面。
- 打开需要设置数据的弹窗时，在显示前或显示过程中调用对应 ViewModel 的加载方法。
- 侧边栏与弹窗都不得替换、清空或重建当前聊天会话。

## 五、弹窗功能形态

同一数据可能存在不同入口形态：

- “纯库模式”：从侧边栏或设置入口进入，只管理全局规则、文档或资源。
- “窗口配置模式”：从当前窗口功能入口进入，除管理内容外，还提供当前窗口启用、可见性、选择或覆盖配置。

两种形态优先复用同一个 Composable，通过明确的 `mode`、窗口状态和回调参数区分，不复制两套近似 UI。

## 六、输入区弹窗层级

输入框上方的 Agent、窗口设置、可见性与渲染、提示词入口均为当前聊天窗口的一级入口：

- 从聊天界面直接打开时，关闭后返回聊天界面。
- 如果未来从这些弹窗继续打开编辑器、选择器或详情弹窗，子弹窗关闭后必须返回原弹窗。
- 弹窗最终内容应依据后续参考图复刻；在参考图到达前允许保留挂载点，但挂载点也必须遵守统一关闭和返回规则。

## 七、带编辑功能弹窗的统一规范

带编辑功能的弹窗属于当前上级页面的子层，必须显示在上级页面上方，并清楚体现“正在编辑上级页面中的某个对象或配置”的层级关系。

### 层级与遮挡

1. 编辑弹窗必须覆盖在发起它的上级页面之上，不得替换、关闭或重建上级页面。
2. 编辑弹窗的顶部必须遮挡上级页面的顶部区域，包括上级页面的标题栏、关闭按钮和顶部操作区，避免两个标题栏或两组关闭按钮同时可操作。
3. 上级页面在编辑弹窗显示期间继续保留状态，但不接收点击、滚动、键盘快捷键或返回事件。
4. 编辑弹窗的遮罩只作用于其直接上级页面；关闭编辑弹窗后恢复该上级页面及其原有滚动位置、筛选条件、选中项和未提交状态。
5. 编辑弹窗内部打开更深层选择器或确认框时，继续按同一规则逐层覆盖，并由最上层界面独占交互。

### 底部操作区

1. 具有可提交编辑内容的弹窗，底部必须提供固定操作区，其中包含明确的“保存”按钮。
2. 保存按钮固定在弹窗底部，不随中间表单内容滚动；表单内容较长时，仅中间内容区滚动。
3. 保存成功后返回直接上级页面，并让上级页面立即显示已保存结果。
4. 保存失败时保留编辑弹窗和用户输入，展示可理解的错误信息，不得关闭弹窗或丢失内容。
5. 存在尚未保存的修改时，点击关闭按钮、外部遮罩或执行系统返回操作，必须采用统一的放弃修改策略；不得静默丢弃用户输入。
6. “保存”并非所有弹窗的强制按钮。只有具备新增、编辑、修改配置或提交表单功能的弹窗必须显示保存按钮；纯查看、选择后立即生效、状态提示、确认操作或无可编辑内容的弹窗可以不显示。
7. 不需要保存按钮的弹窗，也必须遵守统一的层级遮挡、关闭返回和事件不穿透规则。
8. 如功能还需要“取消”“删除”“重置”“应用”等操作，应放在同一固定底部操作区，并保持主操作与危险操作的视觉层级清晰。

### 推荐结构

编辑弹窗统一采用三段式结构：

- 顶部：固定标题栏和关闭入口。
- 中部：可滚动的编辑内容区。
- 底部：按功能需要显示取消、保存和其他操作按钮的固定操作区。

公共弹窗壳应通过明确参数控制底部操作区，例如是否显示保存按钮、保存是否可用、保存中状态、保存回调和放弃修改处理，避免各编辑面板自行拼装出不一致的按钮位置与关闭行为。

## 八、验证要求

完成弹窗或覆盖层修改后至少验证：

1. 标题栏关闭按钮返回正确上级。
2. 点击遮罩返回正确上级。
3. 点击弹窗内部不会意外关闭。
4. 子弹窗关闭后父弹窗仍存在且状态未丢失。
5. 从侧边栏进入的弹窗关闭后恢复侧边栏。
6. 从设置总入口进入的弹窗关闭后恢复设置总入口。
7. 系统返回操作与关闭按钮行为一致。
8. 亮色与暗色主题中遮罩、Surface、边框、文字和图标均可辨识。
9. 运行对应 Gradle 编译任务，并检查 VS Code diagnostics；若 diagnostics 未覆盖 Kotlin 文件，应明确以 Gradle 编译结果为主要验证依据。
